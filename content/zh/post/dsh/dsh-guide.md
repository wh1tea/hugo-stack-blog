> dsh（DeepSeek Harness）是 DeepSeek 官方开源的编码 Agent 工具，跑在你自己的机器上，用浏览器操作。给它一个工作目录，它就能读写文件、执行命令、搜索网页，还能调用你放在磁盘上的「技能」。本文回答两个问题：它是什么，以及一条命令启动后怎么用。

---

## 一、dsh 是什么

先说定位。dsh 属于**编码 Agent（coding agent）**这个品类，和 Claude Code、OpenAI 的 Codex CLI 同类：你说需求，它自己看代码、改文件、跑命令、验证结果。

它和网页版 AI 对话的区别在于三点：

| 维度     | 网页版对话         | dsh                    |
| -------- | ------------------ | ---------------------- |
| 运行位置 | 厂商服务器         | 你的机器，本地进程     |
| 能力     | 只能生成文本       | 真正读写文件、执行命令 |
| 上下文   | 你粘贴什么它看什么 | 可直接检索工作目录     |

关键约束也要说清楚：**模型本身仍然在云端**。dsh 是本地运行的调度层，负责把文件内容、命令输出组织成上下文发给模型，再执行模型给出的动作。所以它需要联网，也需要一个模型 API Key。

架构上 dsh 是「一切皆插件」：界面、模型接入、工具、权限控制都是可插拔的插件行。这解释了它为什么能换模型、能接 MCP、能自定义工作流——但初学阶段不用关心，知道有这层就够了。

---

## 二、它能做什么

dsh 把能力做成一组**工具（tool）**交给模型调用。日常最常触发的是这些：

| 工具                       | 作用                                       |
| -------------------------- | ------------------------------------------ |
| `read` / `write` / `edit`  | 读文件、写文件、做定点修改                 |
| `glob` / `grep`            | 按文件名模式找文件、按内容搜索             |
| `pwsh` / `bash`            | 执行 shell 命令（Windows 上是 PowerShell） |
| `web_search` / `web_fetch` | 联网搜索、抓取网页正文                     |
| `todo_write`               | 把多步任务列成清单，便于跟踪               |
| `subagent`                 | 派生子智能体并行处理独立子任务             |
| `skill`                    | 加载一个技能，按其中的步骤执行             |

还有一类不是「工具」但同样重要的能力：

- **技能（skill）**：磁盘上的 markdown 说明书。放好后 dsh 就能在需要时加载，相当于给它一本可随时翻的手册。
- **全局指令**：`~/.dsh/AGENTS.md`，每个会话自动注入，用来固定长期偏好。
- **计划模式（plan mode）**：先出方案不动手，你确认后再执行。

## 三、启动

前置只有一个：Node.js 18+。启动命令就是一条：

```bash
npx @deepseek-ai/dsh web
```

首次运行会自动下载依赖、初始化配置，然后启动 Web UI 并打开浏览器，默认地址 `http://127.0.0.1:3080`。启动后：

1. **配模型**：在 Settings → Models 里填 DeepSeek API Key，填完立刻可用，不用重启。
2. **选工作目录**：用 Choose workspace 指定一个目录。dsh 以它为根，只能读写其中内容——这一步不做就没法新建会话。

这两个步骤、安装细节和启动时的依赖警告，详见 [dsh 安装与首次使用](dsh-installation.md)。[^1]

`dsh web` 是 `--profile web` 的别名。除此之外还有几个入口：想跑一次性的任务用 `--profile headless`，接入编辑器或自动化客户端用 `--profile acp`。刚开始用不到，知道存在即可。

启动时所在的目录会成为默认 workspace 根目录：

```bash
cd ~/projects/my-app
npx @deepseek-ai/dsh web
```

## 四、典型使用流程

一个会话基本是这个节奏：

1. **选工作目录**（Choose workspace），确定它的活动范围。
2. **用自然语言提需求**，比如「看一下登录接口为什么返回 500」。
3. **观察它调用工具**。它会自己读文件、搜代码、跑命令，每一步在界面上可见。
4. **处理权限确认**。默认权限模式是 `workspace-write`：工作区内的修改可以直接做，越界或有风险的操作会弹出确认，由你批准。

所以它不是「问一句答一句」，而是「给目标，看它自己动手」。你的精力主要花在两处：把需求说清楚，以及在关键节点确认权限。

几个顺手的细节：

- 输入框用 `/` 触发命令（`/compact` 压缩上下文、`/export` 导出会话等），用 `@` 引用工作区文件。
- 会话按工作区分组持久保存，关掉浏览器再回来可以接着聊。
- 界面语言、主题在 Settings 里改，只影响显示。

## 五、三个最值得先用的能力

### 技能：让它按你的规范办事

技能就是一个目录，里面放 `SKILL.md`：

```text
~/.dsh/skills/my-skill/SKILL.md
```

文件开头是一段 front matter，`name` 和 `description` 是必填项：

```markdown
---
name: my-skill
description: 这个技能解决什么问题、什么时候该用它
---

## 步骤

1. 先做 A
2. 再做 B
```

放好后无需重启，它会出现在技能目录里；当你的需求和某个技能的 `description` 匹配，模型就会先加载它再动手。技能可以带 `references/`、`scripts/` 等资源，正文里用相对路径引用即可。

dsh 按优先级在几个位置找技能，个人技能建议放用户级目录 `~/.dsh/skills/`，跨项目都能用。

### 计划模式：先看方案再动手

对影响面较大的改动，先让它出方案而不是直接改。方案确认后再执行，能避免「改了一半方向不对」。这比事后回滚便宜得多。

### 全局指令：把长期偏好写一次

`~/.dsh/AGENTS.md` 会在每个会话自动注入。把反复要交代的事写进去，比如代码风格、汇报偏好、禁止事项，就不用每次重复。

## 六、几个现实提醒

- **它是 developer preview**。迭代快，可能有破坏性更新，别把它当稳定依赖固定在生产流程里。
- **权限边界要自己把关**。`workspace-write` 允许它在工作区内自由改文件，重要改动建议在版本控制下进行，出问题能回退。
- **配置集中在 `~/.dsh/`**。profile（`profiles/`）、会话记录（`sessions/`）、技能（`skills/`）、全局指令都在这里，备份或迁移只需要处理这一个目录。
- **按需认识即可**，不必一上来把插件和 overlay 全看完。用熟了再深入。

## 结语

dsh 的入门路径很短：一条 `npx` 命令启动 → 配 Key、选工作目录 → 用对话下需求、在权限弹窗上做判断。它把你的机器当成工作台，模型负责决策，工具负责动手。
