## 前言

数据结构与算法是计算机科学的核心基础。学习这门课最好的方式不是死记硬背理论，而是**问题驱动**——每个数据结构都是为了解决特定问题而出现的。数组解决连续内存访问的问题，链表解决动态插入的问题，树解决层级关系的问题……理解"为什么需要它"，比记住它的效率特性重要得多。

本文将系统梳理核心概念，涵盖复杂度分析、常见数据结构的分类与实现思路，帮助你搭建完整的知识框架。

## 什么是算法？什么是数据结构？

- **算法**：为解决特定问题而设计的一系列清晰的、有限步骤的指令或操作方法。
- **数据结构**：计算机中存储、组织数据的方式。

两者的关系可以用一个比喻来理解：**数据结构是积木，算法是拼积木的方法**。好的数据结构让算法更高效，好的算法让数据结构发挥最大价值。

## 复杂度分析

复杂度分析是衡量算法效率的标尺，分为时间复杂度和空间复杂度。

### 时间复杂度

渐进时间复杂度（大 O 表示法）描述算法执行时间随数据规模增长的趋势：

| 复杂度     | 名称       | 示例                   |
| ---------- | ---------- | ---------------------- |
| O(1)       | 常数阶     | 数组随机访问           |
| O(log n)   | 对数阶     | 二分查找               |
| O(n)       | 线性阶     | 遍历数组               |
| O(n log n) | 线性对数阶 | 归并排序、快速排序     |
| O(n²)      | 平方阶     | 冒泡排序、嵌套循环     |
| O(2ⁿ)      | 指数阶     | 递归斐波那契（未优化） |
| O(n!)      | 阶乘阶     | 旅行商问题暴力解       |

分析技巧：

- 忽略常数项和低阶项，只关注增长最快的部分
- 加法法则：总复杂度等于量级最大的那段代码的复杂度
- 乘法法则：嵌套循环的复杂度等于内外层复杂度之积

### 空间复杂度

衡量算法运行时占用的额外存储空间，同样用大 O 表示法：

- **O(1)**：只使用常数个额外变量（就地排序）
- **O(n)**：需要额外数组或线性存储（归并排序）
- **O(n²)**：二维辅助数组

**时间复杂度与空间复杂度通常是权衡关系**——用空间换时间（如缓存），或用时间换空间（如内存受限环境）。

## 数据结构的分类

### 逻辑结构

逻辑结构揭示了数据元素之间的逻辑关系。在数组和链表中，数据按一定顺序排列，体现线性关系；在树中，数据从顶部向下按层次排列，表现"祖先"与"后代"的派生关系；图则反映了复杂的网络关系。

#### 线性结构：一对一

元素之间呈线性排列，是最直观的一类结构。

| 结构     | 特点                                      | 常见操作         |
| -------- | ----------------------------------------- | ---------------- |
| **数组** | 连续内存，随机访问 O(1)，插入/删除 O(n)   | 遍历、修改、排序 |
| **链表** | 非连续内存，随机访问 O(n)，插入/删除 O(1) | 遍历、反转、合并 |
| **栈**   | 后进先出（LIFO），羽毛球筒                | 入栈、出栈、栈顶 |
| **队列** | 先进先出（FIFO），排队                    | 入队、出队、队首 |

#### 非线性结构：一对多 / 多对多

- **树形结构**：一对多关系
  - **树**：分层结构，根节点、叶子节点
  - **堆**：特殊的完全二叉树，大顶堆/小顶堆
  - **哈希表**：键值对映射，可看作一对多的索引结构
- **网状结构**：多对多关系
  - **图**：由节点和边构成，反映复杂网络关系

### 物理存储结构

所有数据结构本质上都是基于**数组、链表或二者的组合**实现的：

| 数据结构 | 可用实现方式                       |
| -------- | ---------------------------------- |
| 栈       | 数组（顺序栈）/ 链表（链式栈）     |
| 队列     | 数组（循环队列）/ 链表（链式队列） |
| 哈希表   | 数组 + 链表（链地址法）            |
| 树 / 堆  | 数组（堆）、链表（二叉树）         |
| 图       | 数组（邻接矩阵）/ 链表（邻接表）   |

**数组**在初始化后长度不可变，是"静态数据结构"；**链表**可在运行时调整长度，是"动态数据结构"。不过数组通过重新分配内存也能实现长度变化，具备一定"动态性"。

## 核心数据结构详解

### 1. 数组（Array）

- **存储方式**：连续内存空间，每个元素大小相同
- **关键特性**：随机访问 O(1)，插入/删除需移动元素 O(n)
- **经典场景**：查字典（索引查找）、矩阵运算、实现其他数据结构
- **变体**：动态数组（如 C++ vector、Java ArrayList），自动扩容

### 2. 链表（Linked List）

- **存储方式**：节点通过指针串联，内存不连续
- **关键特性**：插入/删除 O(1)（已知位置），随机查找 O(n)
- **分类**：单链表、双向链表、循环链表
- **应用**：LRU 缓存、哈希表链地址法、文件系统 FAT

### 3. 栈（Stack）

- **特点**：后进先出（LIFO），像羽毛球筒，只能从一端操作
- **核心操作**：push（入栈）、pop（出栈）、top（栈顶）
- **经典应用**：函数调用栈（递归）、括号匹配、表达式求值、浏览器的后退功能

### 4. 队列（Queue）

- **特点**：先进先出（FIFO），像排队，只能在队尾入、队首出
- **变体**：循环队列（解决假溢出）、双端队列（Deque）、优先队列（基于堆）
- **经典应用**：BFS（广度优先搜索）、消息队列、任务调度、打印队列

### 5. 哈希表（Hash Table）

- **核心思想**：通过哈希函数将键映射到数组索引，实现近乎 O(1) 的查找
- **冲突解决**：链地址法（数组+链表）、开放寻址法、再哈希法
- **哈希函数**：直接定址法、除留余数法、平方取中法
- **负载因子**：元素个数/桶数，超过阈值触发扩容
- **应用**：数据库索引、缓存系统、字典实现

### 6. 树（Tree）

- **特点**：分层结构，每个节点有父节点和若干子节点
- **常见类型**：
  - **二叉树**：每个节点最多两个子节点
  - **二叉搜索树（BST）**：左 < 根 < 右，中序遍历有序
  - **AVL 树 / 红黑树**：自平衡 BST，保证最坏 O(log n)
  - **堆**：大顶堆（根最大）和小顶堆（根最小），用于优先队列
- **遍历方式**：前序、中序、后序、层序

### 7. 图（Graph）

- **组成**：顶点（Vertex）+ 边（Edge）
- **分类**：有向图 / 无向图、加权图 / 无权图
- **存储方式**：邻接矩阵（稠密图）、邻接表（稀疏图）
- **经典算法**：
  - 遍历：DFS（深度优先）、BFS（广度优先）
  - 最短路径：Dijkstra、Bellman-Ford、Floyd
  - 最小生成树：Kruskal、Prim
  - 拓扑排序：Kahn 算法、DFS 后序

## 算法学习路线

如果你刚开始系统刷算法，推荐以下路线：

1. **基础阶段**（1-2 周）
   - 掌握复杂度分析
   - 熟练数组、链表、栈、队列的增删改查
2. **核心阶段**（3-6 周）
   - 哈希表应用、双指针、滑动窗口
   - 二叉树遍历与递归、堆与优先队列
   - 排序算法（快排、归并、堆排）
3. **进阶阶段**（7-10 周）
   - 动态规划、回溯、贪心
   - 图论基础（DFS/BFS 变形、最短路径）
   - 并查集、字典树、线段树

实践建议：从 **查字典**（哈希/二分）、**扑克整理**（插入排序）、**货币找零**（贪心/动态规划）这些生活化场景切入，先理解"为什么需要"，再深入"怎么写代码"。

## 总结

数据结构与算法是一门问题驱动的学科。核心要点：

- **复杂度分析**是衡量算法好坏的客观标准
- **数组和链表**是所有数据结构的两大基石
- **线性结构**（栈、队列）侧重顺序操作
- **非线性结构**（树、图、哈希表）解决更复杂的映射和关系问题
- **先理解为什么，再学习怎么做**——带着问题去学习，才能真正感受数据结构的美
