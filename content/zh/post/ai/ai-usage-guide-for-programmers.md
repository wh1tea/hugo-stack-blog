这不是一篇教你"用 AI 取代程序员"的鸡汤。这是一篇教你**如何让每一分钱、每一个 Token 都花在刀刃上**的实战手册。

---

## 一、先搞清楚：你要的是什么？

程序员用 AI，不外乎三类场景：

| 场景           | 目标                         | 适合的工具形态                          |
| -------------- | ---------------------------- | --------------------------------------- |
| **编码助手**   | 补全代码、写测试、重构       | IDE 插件（Copilot / Cursor / Continue） |
| **对话式开发** | 复杂功能实现、调试、架构设计 | Agent（Claude Code / Hermes / Codex）   |
| **知识问答**   | 查文档、学新技术、Debug 思路 | 聊天（ChatGPT / Claude / DeepSeek）     |

**最常见的错误：** 拿聊天窗口写代码，拿 Agent 查文档。工具错配，效率和成本都是灾难。

### 1.1 IDE 插件类（Copilot / Cursor / Continue）

- **适合**：逐行补全、写单元测试、生成样板代码
- **不适合**：跨文件的复杂重构、需要全局理解的任务
- **费用**：Copilot $10/月，Cursor Pro $20/月
- **使用频率**：全天候，每次交互成本极低

### 1.2 Agent 类（Claude Code / Hermes / Codex）

- **适合**：实现完整功能、多文件修改、架构重构、调试疑难 Bug
- **不适合**：简单问答、单行补全（杀鸡用牛刀）
- **费用**：按 Token 计费，一次复杂任务可能 $0.5-$5
- **使用频率**：每天 3-10 次深度使用

### 1.3 聊天类（ChatGPT / Claude / DeepSeek Chat）

- **适合**：学习新技术、理解概念、代码审查思路
- **不适合**：写需要精确控制的生产代码（容易产生幻觉）
- **费用**：免费版已够用，Pro 版 $20/月
- **使用频率**：随时，查资料首选

## 二、Prompt 工程：让 AI 说人话的关键

### 2.1 通用原则：上下文 > 指令

❌ 坏 Prompt：

> "帮我写一个用户登录功能"

✅ 好 Prompt：

> "我正在用 Python + FastAPI + SQLAlchemy 写一个 Web 应用。
> 需要实现用户登录功能，使用 JWT token 认证，密码用 bcrypt 加密。
> 数据库表 users 已有 email 和 password_hash 字段。
> 请帮我写登录的 API 端点，包括：
>
> 1. 请求验证（email 格式、密码长度）
> 2. 密码验证逻辑
> 3. JWT token 生成和返回
> 4. 错误处理（用户不存在、密码错误）
>    注意：不需要注册功能，注册已经有实现了。"

**原则：Tell it what you have, what you want, and what you don't want.**

### 2.2 给 AI 一个"角色"

> "你是一个有 15 年经验的 Python 后端工程师，擅长编写高并发、可维护的代码。
> 请 review 以下代码，重点检查：线程安全、内存泄漏、边界情况..."

角色设定不是玄学，它能激活模型在特定领域的知识分布（Claude 在"资深工程师"模式下输出质量明显更高）。

### 2.3 分步式 Prompt（Chain of Thought）

一次让 AI 做一件复杂的事，不如拆成几步：

第 1 步："先分析这个系统的数据库 schema，告诉我潜在的性能问题"
第 2 步："基于分析结果，给出索引优化建议"
第 3 步："根据优化方案，生成迁移脚本"

每一步的结果作为下一步的上下文。这样比一次丢一个大任务质量高得多，而且如果某一步错了，只需要调整那一步，不用重新来。

### 2.4 用示例（Few-shot）控制输出格式

"请将以下 Git log 按格式生成 CHANGELOG：

示例：

- feat(api): 添加用户注册接口 (#123)
- fix(auth): 修复 Token 过期判断逻辑 (#122)
- refactor(db): 重构查询方法以提升性能 (#121)

输入：
[git log 内容]"

## 三、Token 节约的艺术

Token 就是钱。对于使用 API 的开发者来说，掌握 Token 优化等于直接降低使用成本。

### 3.1 控制上下文窗口

AI 模型按**输入 Token + 输出 Token** 双重计费。输入部分是大头。

**省钱策略：**

| 策略            | 做法                                                         | 效果             |
| --------------- | ------------------------------------------------------------ | ---------------- |
| 精确截断上下文  | 只粘贴相关函数，不粘贴整个文件                               | 减少 50-80% 输入 |
| 定期清理会话    | 过长的历史就是燃烧的 Token                                   | 减少 30-60% 输入 |
| 用摘要代替原文  | "上一个函数返回了一个包含 200 个字段的 JSON，其中 id 是 xxx" | 减少 90%+        |
| 控制 max_tokens | 输出设 1000 Token 而不是 4096                                | 减少输出浪费     |

### 3.2 实际案例对比

**❌ 浪费型（一个月多花 $50-100）：**

> "下面是我的完整项目代码（粘贴 5000 行），帮我找 Bug"

**✅ 节约型：**

> "我的项目结构是：
>
> - src/api/routes.py（负责路由）
> - src/services/user_service.py（负责业务逻辑）
> - src/models/user.py（数据库模型）
>
> Bug 现象：登录接口返回 500，错误日志：'TypeError: Object of type User is not JSON serializable'
> 相关代码（只粘贴 user.py 和 routes.py 中 login 路由）：
> [代码片段]

同样解决问题，Token 消耗减少一个数量级。

### 3.3 选择正确的模型

不同模型的价格差距巨大——**选对模型比任何技巧都省钱**：

| 模型             | 输入价格 / 1M Tokens | 适合场景              |
| ---------------- | -------------------- | --------------------- |
| Claude Opus 4    | $15                  | 最复杂的架构决策      |
| Claude Sonnet 4  | $3                   | 日常编码主力          |
| GPT-4o Mini      | $0.15                | 简单问答、格式转换    |
| DeepSeek V3      | $0.14                | 中文场景、替代 Sonnet |
| Gemini 2.5 Flash | $0.15                | 批量处理、轻量任务    |

**策略：日常用中端模型（Sonnet / DeepSeek），疑难杂症切高端（Opus），简单任务用微型（Mini / Flash）。**

### 3.4 善用 Agent 工具的上下文管理

如果使用 Hermes Agent 或 Claude Code 这类工具：

- **用 `/compress`** 手动压缩上下文（Hermes 在 Token 使用达到 50% 时自动触发，你也可以手动触发）
- **开启 Checkpoints** 但注意它消耗额外 Token 记录文件状态
- **独立会话做独立任务**——一个会话干一件事，干完就结束
- **避免长对话不重置**——超过 20 轮的对话，前 15 轮的细节模型已经记不清了，但 Token 还在烧

### 3.5 估算你的实际成本

一个公式估算月花费：

> 月成本 ≈ 每日任务数 × 每任务平均输入 Tokens × 2（输出系数）× 价格/M × 工作日

举例：每天 10 个任务，每个任务平均输入 8K Tokens，用 Sonnet 4（$3/M）：

> 月成本 = 10 × 8000 × 2 × 3/1000000 × 22 = $10.56

如果用 Opus 4（$15/M）：

> 月成本 = 10 × 8000 × 2 × 15/1000000 × 22 = $52.80

5 倍差距。这就是为什么"日常用中端、疑难用高端"的策略一年能省几百美元。

## 四、给程序员的实操技巧

### 4.1 代码生成的黄金法则

**法则 1：永远不要盲信 AI 生成的代码**

AI 代码看似正确，但在边界条件、并发安全、错误处理上经常翻车。正确的姿势：

> 1. AI 生成 → 2. 人工审查 → 3. 单元测试覆盖 → 4. 集成测试验证

**法则 2：AI 写测试，你写逻辑**

让 AI 写单元测试是目前 ROI 最高的用法。测试用例需要覆盖全面但不需要创造力，AI 恰好擅长这个。

> "给定以下函数，帮我写 pytest 测试用例，覆盖：
>
> - 正常输入
> - 空列表
> - None 输入
> - 超大数值
> - 类型错误"

**法则 3：让 AI 解释，而不是让它猜**

> ❌ "这段代码有 Bug 吗？"（AI 只能猜）
> ✅ "这段代码在这种输入下会出问题吗：[具体输入]。为什么？"（AI 可以推理）

### 4.2 Debug 的正确姿势

Debug 是 AI 最被低估的能力。正确的 Debug Prompt 写法：

> ## 问题描述
>
> 接口 /api/users/login 返回 500，其他接口正常。
>
> ## 错误日志
>
> Traceback (most recent call last):
> File "app.py", line 42, in login
> user = User.query.filter_by(email=email).first()
> TypeError: 'NoneType' object is not subscriptable
>
> ## 相关代码
>
> @app.route('/api/users/login', methods=['POST'])
> def login():
> data = request.get_json()
> email = data['email'] # line 42
> password = data['password']
> ...
>
> ## 我已尝试
>
> 1. 确认 POST 请求有 Content-Type: application/json
> 2. 打印 data 变量发现它是 None
>
> ## 问题
>
> 为什么 data 是 None？怎么修复？

给的上下文越精确，AI 的诊断越准确。重要的是告诉 AI **你已尝试过什么**——这能避免 AI 给出你已经排除掉的方案。

### 4.3 使用 AI 做代码审查

> "请作为 Code Reviewer 审查以下代码变更，按优先级排序：
>
> 1. **安全问题**（SQL 注入、XSS、敏感信息泄露）
> 2. **性能问题**（N+1 查询、不必要的循环、大对象复制）
> 3. **可维护性**（命名、注释、函数长度、重复代码）
> 4. **正确性**（边界条件、类型错误、竞态条件）
>
> 代码 Diff：
> [粘贴 diff]

AI Code Review 的最佳时机是 **PR 提交前**，而不是提交后。让 AI 先过一遍，修掉明显的问题，再让人审查——这样人的精力集中在真正的架构和设计决策上。

### 4.4 架构设计：让 AI 做你的"白板对手"

> "我需要设计一个实时协作编辑器（类似 Google Docs），
> 后端用 Go，前端用 React。
> 请从以下几个方面分析架构：
>
> 1. 如何解决冲突合并（CRDT vs OT）？
> 2. WebSocket 连接管理的最佳方案？
> 3. 数据持久化策略（如何保证不丢数据）？
> 4. 扩展性瓶颈在哪里？
>
> 不需要写代码，只需要架构级的分析和方案对比。"

这种方式下 AI 充当一个经验丰富的架构师跟你脑暴。关键是要让它**给选型依据**而不是"哪个最好"——没有银弹，只有 trade-off。

### 4.5 学习新技术的最佳姿势

> "我想学习 Rust 的所有权系统。我有 5 年 Go 开发经验。
> 请用 Go 的概念类比来解释：
>
> 1. 什么是所有权？→ 类比 Go 的什么概念？
> 2. 什么是借用？→ 跟 Go 的指针有何不同？
> 3. 什么是生命周期？→ 跟 Go 的逃逸分析有关吗？
> 4. 实际编码时最容易踩的 3 个坑是什么？
>    "

**用你已有的知识锚定新知识**，这个 Prompt 模式可以套用到任何技术栈转换场景。

## 五、工具链的协同使用

### 5.1 生产级工作流

> Copilot（IDE 补全，全天候）
> ↓
> Agent（实现功能模块，按需调用）
> ↓
> AI Code Review（PR 前检查）
> ↓
> CI/CD 自动化测试

每一层解决不同粒度的问题，互不替代。

### 5.2 [没有银弹](https://en.wikipedia.org/wiki/No_Silver_Bullet)：不同工具适合不同语言

| 语言/场景           | 推荐工具               | 原因                        |
| ------------------- | ---------------------- | --------------------------- |
| Python/TypeScript   | Claude Code / Hermes   | 对动态语言理解好            |
| Rust/C++            | Claude Sonnet 4        | 对复杂类型系统处理强        |
| Java/C#             | Copilot + ChatGPT      | 生态成熟，IDE 补全就够      |
| Go                  | DeepSeek / Claude 均可 | 语言简单，模型差异不大      |
| 前端（React/Vue）   | Cursor + Claude        | 需要实时预览，Cursor 集成好 |
| DevOps (Docker/K8s) | Hermes / Claude Code   | 需要执行命令、操作文件      |

### 5.3 国内用户的特殊考量

- **网络问题**：OpenRouter 国内可用但延迟高，推荐 DeepSeek 或阿里 Qwen 直连
- **支付问题**：OpenRouter 支持支付宝，Anthropic 需海外信用卡
- **替代方案**：DeepSeek 在中文和代码任务上已是国际一流水平，且国内直接访问
- **数据隐私**：重要代码不要上传给境外服务，考虑本地模型（Qwen 2.5 32B）

## 六、常见误区

| 误区                         | 现实                                                                    |
| ---------------------------- | ----------------------------------------------------------------------- |
| "AI 写的代码可以直接用"      | 不能。必须审查、测试、审查。                                            |
| "Prompt 越长越好"            | 不是。上下文中有用信息密度才是关键。                                    |
| "一个会话用到底"             | 不该。长会话的 Token 成本和模型质量衰减都不值得。                       |
| "最贵的模型就是最好的"       | 不是。Opus 写简单 CRUD 跟 Sonnet 没区别，但贵 5 倍。                    |
| "AI 能替代架构师"            | 不能。AI 可以给方案，但做决策的永远是你。                               |
| "用中文提问效果差"           | 不一定。对国产模型（DeepSeek/Qwen）中文更好；对 Claude 用英文效果稍好。 |
| "复制整个项目给 AI 效果最好" | 错。信息密度太低，AI 反而抓不住重点。                                   |

## 七、底线原则

1. **AI 是加速器，不是自动驾驶**——你仍然需要理解代码在做什么
2. **不要在 AI 面前暴露生产环境的敏感信息**——API Key、数据库密码、客户数据
3. **AI 帮助你思考，而不是代替你思考**——如果它做一个决策而你不理解为什么，停下来
4. **持续学习基本功**——正则表达式、SQL、Git、数据结构，这些 AI 帮你写，但你需要能审
5. **定期回顾你的 AI 使用模式**——你是在利用它，还是在被它带着走？

---

## 八、总结

程序员用好 AI，核心只有三件事：

1. **选对工具**——补全用 Copilot/Cursor，开发用 Agent (Hermes/Claude Code)，问答用 ChatGPT
2. **写对 Prompt**——给上下文、给约束、分步骤、用示例
3. **管好 Token**——控制上下文、选合适模型、按场景切换

做到这三点，AI 就是你的超级加速器。做不到，AI 只是另一个让你更焦虑的玩具。
