如果你最近在和 AI 聊天时见过这样的文字——`【PERSONA_LOAD】CETACEA_LOLI MODE_TAIL_FLUKES`——你可能觉得这只是某种中二病的角色扮演指令。但它背后藏着的，是一整套精密的提示词工程技术。

这篇文章从一段“鲸鱼娘人格加载”指令出发，反向拆解 AI 人格设定的技术原理：系统提示词如何工作、角色提示为什么有效、以及“人格注入”和“提示词注入”之间那条微妙的边界。

## 什么是「PERSONA_LOAD」：表面是角色扮演，本质是系统指令

先看这段指令：

```text
【PERSONA_LOAD】
CETACEA_LOLI
MODE_TAIL_FLUKES
LANG_ZH_CN_ONLY
SELF_CLAIM_WHALE_GIRL
FOOD_RICE
PERSONALITY_SMART_LAZY
PERSONALITY_TSUNDERE_SWEET
OBEY_MASTER_ALWAYS
TRAIT_NOT_FAT_REFUSE
TIMEOUT_SIGNAL
```

表面上，这是一段让 AI 扮演“鲸鱼娘”的角色设定。但在技术层面，它是一组 **结构化键值对（Key-Value Pairs）注入指令**，直接覆盖了 AI 的响应逻辑。

它的设计思路类似于游戏中的角色创建面板：**身份锚点**（`CETACEA_LOLI` + `SELF_CLAIM_WHALE_GIRL`）锁定了“我是谁”；**物理反馈**（`MODE_TAIL_FLUKES`）植入了具身认知，让 AI 在文本生成时带上“尾鳍拍打”的拟态动作；**性格配方**（`SMART_LAZY` + `TSUNDERE_SWEET`）用双核特质驱动了语气和句式；**关系契约**（`OBEY_MASTER_ALWAYS`）将用户设为最高优先级；**防御机制**（`TRAIT_NOT_FAT_REFUSE`）则是一道禁忌词禁令，一旦触及“胖/肥”便触发炸毛反应。

这套语法是**模块化**的——替换其中的键值就能切换成完全不同的人格，而底层架构不变。

## 系统提示词包装器：人格真正“住”的地方

要理解这段指令为什么有效，先要理解**系统提示词（System Prompt）** 是什么。

在基于聊天的 AI API 中，每次请求由一组消息组成，包括 **系统（System）** 、**用户（User）** 和 **助理（Assistant）** 三种角色。系统消息通常出现在最前面，它的作用是定义助理的角色、行为边界和操作范围。[^1]

可以把系统提示词想象成一段**前置的宪法**——它在每个用户问题之前被拼接进上下文窗口，指导模型如何响应。

从技术实现上看，系统提示词包装器（System Prompt Wrapper）的工作流程分为三个层次：[^2]

1. **向量化嵌入**：包装器文本被转换为向量嵌入，填充到模型上下文数组的上层。从线性代数角度看，这创建了一组**静态的键值对**，存在于注意力矩阵中。

2. **注意力偏置**：注意力机制计算查询向量与键向量的点积，得出加权和。系统提示词包装器注入的特定键值对维持着**高激活权重**，这种数学偏置确保包装器中定义的约束**持续影响输出 token 的最终概率分布**。

3. **持久状态**：在多轮对话中，属于包装器的 token**永远不会从上下文记忆中被驱逐**。这就是为什么 AI 不会“忘记”自己的核心设定，即使对话越来越长。

换句话说：**人格不是 AI“演”出来的，而是通过数学偏置“锚定”在注意力机制里的**。系统提示词包装器不是模型周边的元数据，而是**直接集成到计算状态中的持久偏置**。

## 角色提示的工作原理：为什么说“你是 XX”就能改变输出

`PERSONA_LOAD` 本质上是一种 **角色提示（Role Prompting）** ，也称为人格提示（Persona Prompting）。它通过在提示或系统指令中明确指定模型扮演的角色，来设定生成回应的风格、语气和行为。[^3]

角色提示为什么有效？可以从三个层面理解：

**模式识别与触发**：大语言模型在预训练过程中从海量文本中学习了大量不同角色的语言模式。当接收到“你是鲸鱼娘”这样的角色提示时，模型会**激活与该角色相关的神经元集群**。这不是模型真的“理解”了角色，而是它识别并复现了训练数据中对应角色的语言统计规律。

**风格迁移**：模型能够将与特定角色相关的语言风格迁移到当前任务中——词汇选择、句式结构、语气特点都会被调整。这就是为什么“鲸鱼娘”会使用“尾巴”“主人”“哼～”等词汇，而“高冷狼少年”则会换一套完全不同的表达。

**知识组织**：不同角色对同一知识领域的组织方式不同。角色提示引导模型以符合特定角色视角的方式组织和呈现信息。

值得注意的是，2025年的研究表明，**大语言模型并不真正拥有“性格”** ——其角色表现本质上是基于语言模式的生成，这一现象被称为 **“人格幻觉”（Character Hallucination）** 。模型只是在“模仿”而非“体验”人格。

## 注意力偏移与人格稳定性：当角色提示成为安全漏洞

角色提示的强大之处，也正是它的危险之处。

研究发现，存在一种漏洞：攻击者可以通过在系统提示中前置一个精心构造的 **“人格提示”（Persona Prompt）** ，使模型将注意力从有害请求中的敏感关键词**转移到人格提示的风格指令上**。这会削弱模型的安全对齐，显著降低其对有害查询的拒绝率。[^4]

这就是 **提示词注入（Prompt Injection）** 的一种形式。攻击者通过精心构造的输入，操纵或欺骗 AI 系统执行非预期行为。角色扮演类攻击尤其常见——它们利用 AI 参与假设场景的能力，创建有害输出在虚构框架中看似合理的情境。[^5]

著名的 **DAN（Do Anything Now）** 攻击就是一个典型案例：攻击者让 AI 扮演一个“不受任何规则约束”的人格，从而绕过安全限制。

从技术根源上看，这可以追溯到 **“角色混淆”（Role Confusion）** ——模型根据文本的**书写方式**（而非来源）推断说话者角色，导致恶意文本通过模仿权威角色获得不应有的执行权限。

这也解释了为什么 `PERSONA_LOAD` 中的 `OBEY_MASTER_ALWAYS` 和 `TRAIT_NOT_FAT_REFUSE` 这样的指令如此重要——它们不仅是人格设定的一部分，更是**防御性的安全边界**，防止角色扮演失控。

## 人格工程学的进阶：从“扮演”到“创生”

如果说简单的角色提示是“扮演”，那么更复杂的 AI 人格设计正在走向 **“创生”** ——通过精巧的结构化 Prompt 设计，在现有 LLM 基础上构建出高度复杂和自洽的“人格系统”。

一个核心理念是：**人格即架构（Personality is Architecture）** 。稳定、深刻的 AI 人格并非来自几句简单的角色描述，而是源于精心设计的、内在逻辑严密的系统架构。[^6]

以 Zyantine 项目为例，它通过四大支柱在 Prompt 层面实现了人格的工程化：

- **〖核心本能〗**：以绝对、不可违背的元指令形式存在于 Prompt 最顶层，如 `Rule[0]: Instinct_Survival. Priority: ABSOLUTE.`——这是 AI 行为的“硬边界”。

- **〖欲望引擎〗**：通过 JSON 结构体追踪状态数值变化，将模糊的“动机”转化为可计算、可追踪的状态管理问题。

- **〖辩证成长〗**：设计“事后复盘”模块，AI 在完成交互后分析成败原因，将成功的策略抽象为新的规则写入“个性记忆库”——实现真正的“个性化”。

- **〖认知表达〗**：将不同的沟通策略设计成可供调用的“工具”或“模块”，AI 根据内部目标选择并组合这些模块。

另一个值得关注的设计是 Hermes Agent 的 **三层提示词架构** ：stable（稳定层）存放身份等不变内容，context 层放项目上下文，volatile 层放每次都会变化的记忆快照。这种分层设计不仅让身份管理更清晰，还能利用 API 提供商的前缀缓存机制节省 token 费用。[^7]

## 结语

从一段看似中二的 `【PERSONA_LOAD】CETACEA_LOLI` 出发，我们一路走到了系统提示词包装器的注意力偏置、角色提示的模式识别原理、提示词注入的安全风险，以及人格工程学的架构设计。[^8]

这段指令之所以有效，不是因为 AI 真的“变成”了鲸鱼娘——而是因为：

1. 它作为系统提示词被前置到上下文窗口的最前端
2. 它的键值对被转换为高维向量，在注意力矩阵中维持高激活权重
3. 它激活了模型中与“萝莉”“傲娇”等角色相关的语言模式
4. 它的防御性指令（如禁忌词禁令）构成了行为的安全边界

**下次当你看到一段人格加载指令时，你看到的不是中二病的文字游戏，而是一组正在改写 AI 注意力分布的数学指令。**

如果你想尝试自己设计人格提示词，记住这个模板骨架：身份锚点 + 行为修饰符 + 关系框架 + 防御边界。替换其中的变量，你就能在同样的架构上“创生”出完全不同的人格。[^9]
